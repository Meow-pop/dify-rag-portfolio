# AI Automation 岗位能力路线

这类岗位的核心不是训练基础模型，而是把 AI、自动化、数据库和业务系统集成为可交付的软件。

## 能力优先级

### P0：必须能独立完成

1. **业务流程建模**：把口头需求画成触发条件、步骤、状态、异常和人工确认点。
2. **HTTP / REST / Webhook**：理解请求方法、JSON、认证、分页、限流、超时与重试。
3. **n8n 自动化**：表单或邮件触发、条件分支、循环、等待、定时任务、错误处理和凭据管理。
4. **数据库**：SQL、PostgreSQL、表结构、关系、索引、CRUD、事务和基本权限控制。
5. **编程基础**：优先 Python，并能读写 JavaScript / TypeScript；会调试和处理异常。
6. **Git / GitHub**：分支、提交、README、Issue、Pull Request 和密钥防泄露。

### P1：形成 AI 应用竞争力

1. **LLM API**：消息结构、流式输出、结构化 JSON、工具调用、成本与延迟控制。
2. **RAG**：文档解析、切分、Embedding、向量检索、混合检索、Reranker、引用和评测。
3. **Agent 与 MCP**：工具定义、权限边界、状态管理、失败恢复和人工审批。
4. **轻量 Web 开发**：内部 Dashboard、表单、列表、状态页和 API 服务。
5. **数据处理与采集**：清洗、去重、字段映射、网页抓取合规和增量更新。

### P2：把 Demo 变成工程

1. Docker / Docker Compose、环境变量和持久化卷。
2. Vercel 或云服务器部署、域名和 HTTPS。
3. 日志、监控、告警、备份和恢复。
4. 自动测试、幂等性、限流、重试、失败队列与审计记录。
5. 英文技术文档、异步沟通和演示能力。

## 作品集目标

本仓库最终实现一个安装项目协调助手：

```text
项目创建
  -> 根据 ZIP Code 匹配安装商
  -> 邮件或短信邀请报价
  -> 收集并结构化报价
  -> 对比报价并请求人工确认
  -> 安装日期提醒
  -> 完工确认与照片归档
  -> 项目状态 Dashboard
```

知识库部分使用 Dify 展示 RAG；流程自动化部分使用 n8n；业务数据使用 Supabase/PostgreSQL；自定义逻辑使用 Python API。所有外部发送动作在演示环境中默认进入人工确认节点。

## 面试时需要讲清楚

- 为什么选择这些工具，而不是只说使用了哪些工具；
- 数据从哪里来，如何清洗、建模和权限隔离；
- Webhook 重复投递、API 超时和发送失败如何处理；
- RAG 如何评测，错误回答如何定位；
- 密钥如何管理，哪些动作必须人工确认；
- 如何用日志和指标证明系统真的可运行。
